# Android 0.7.21.21：导入后自动识别缺失歌词

导入的视频歌曲先在原有歌词来源中匹配；无法匹配、标题不足以判断或搜索失败的歌曲，自动读取原视频音频并在本地生成带时间戳的机器字幕。结果直接保存为该视频的歌词，播放时直接显示，不再要求逐首点击「识别」和「应用」。已经手动选择的歌词或纯音乐状态保留。

- 原有两个文本搜索任务之外增加一个串行音频识别任务，下载和识别不会阻塞导入返回。手动校准与自动识别共用同一个模型任务位，避免同时加载多份模型。推理使用独立 Worker、WASM 单线程。
- 保留持久队列的存储键，升级任务格式为版本 2；旧队列中未匹配、待确认和失败的歌曲补做一次自动识别，已完成任务不重复处理。退出应用会终止推理，下次启动从未完成任务继续。
- 歌单显示正在处理的歌曲、进度和等待数，可全局暂停、继续或重试失败项。「自动选择最佳歌词」现有开关同时控制该流程，保留用户原来的关闭选择。
- 保存前以数据库事务检查用户是否已经选择歌词；播放请求结束前重新读取选择，防止较晚返回的空搜索、纯音乐判断或另一份歌词覆盖已生成的字幕。当前播放歌曲没有歌词时，识别完成后直接显示，无需重播。新字幕清除旧歌词的逐曲偏移，保留设备全局偏移。
- 修复 Transformers.js 3.8.1 未指定语言时实际默认英语的问题：每个音频窗口先用 Whisper 的首个解码步骤检测语言，仅比较模型的语言 token，然后明确传入识别语言。
- 机器字幕明确标记来源；空白、明显重复、非有限或越界时间戳不自动保存。保留 15 分钟、64 MiB、20 分钟任务时限以及试听片段拒绝规则，不替换原视频音源。

## 验证

- 自动识别队列、语言判断、播放竞态、持久化及 Omni 架构的 82 项专项单测通过。
- 浏览器实际执行 Omni 导入 → 缺词识别 → 保存 → 播放显示，没有点击任何识别或应用按钮；重新载入不重复下载。另用公开 JFK 语音样本和内置模型完成真实自动识别，未出现默认英语警告。
- 手机宽度下原有手动校准、关闭面板、应用和恢复功能回归通过；TypeScript 检查通过。
- 扩展歌词和平台回归：1890 项通过，1 项跳过；QQ 探索页的 4 项断言、平台枚举的 1 项断言及两个平台测试的 mock 导出错误已在未修改的 0.7.21.20 提交（015251dc）上重现，属于原有测试问题。
- 生产资源用 `test/manual/audio-alignment-built.mjs` 检查真实自动语言识别及零外部模型请求；安装包沿用原签名。

## 边界

自动处理不等于识别准确率保证。当前模型是通用多语言语音识别模型，歌声、重伴奏、合唱及日语转写可能有误；文本和时间戳校验也不代表逐句声学置信度。用户私人收藏夹和实际手机尚未进行端到端验证。音频需要可正常读取，因 403 等错误读不到原音频的歌曲不能通过识别解决。自动工作只在应用仍运行时进行，耗时依设备和歌长而定。
