# Android 0.7.21.19：导入时准备歌词

之前导入只保存视频引用，跨来源歌词检索等到播放时才启动。标题没有标准音乐信息时还会跳过自动匹配，造成用户反复手动搜索。本版在导入成功后异步排入歌词准备队列；打开已存在的收藏夹时，缓存页、首页和后续补页也会排入同一队列。

- 按原媒体身份去重，不改变 B 站视频播放来源，也不以音乐平台是否收录作为可播放条件。收藏夹 141 条的分页与歌词准备互不阻塞。
- 队列最多并发 2 首，每首结束后间隔 500 毫秒；独立保存状态，重新打开应用后恢复未完成任务。单首匹配总预算 90 秒；没有网络或关闭自动歌词设置时停止启动新任务。
- 收藏夹详情和网格导入区显示检查进度、已就绪、待识别和未找到/失败数量，支持暂停全部、继续和重试未解决条目。进度只随任务状态更新，不按播放进度重绘。
- 匹配结果保存到播放器使用的同一个歌词缓存。原子条件写入防止晚到的后台匹配覆盖手动导入、手动匹配和纯音乐选择；已经有选择的歌曲直接跳过搜索。
- 视频标题识别支持 `歌手/歌名`、常见 MV 尾缀与已有日语歌手别名。只有歌名时要求候选歌名完全匹配、时长差不超过 3 秒且匹配结果归属同一歌手；翻唱、现场、解说等模糊信息留待人工判断。
- 新增 LRCLIB 到自动匹配、手动匹配及来源设置。调用其公开 `https://lrclib.net/api/search` 和 `/api/get/{id}`，不附带账户凭据，仅接收带时间戳歌词或明确的纯音乐结果；普通文本不伪装为同步歌词。歌词库结果不会覆盖歌曲元数据。
- AMLL 按平台 ID 找不到歌词后继续直接搜索歌名。批量准备接受第一个可靠的带时间戳结果，避免为追求逐字歌词拖延整张列表。

## 验证

- 歌词及导入准备相关套件：906 项通过，1 项既有跳过；播放、预取、收藏夹与元数据回归：265 项通过（两组有重叠）。补充验证 Omni 导入在歌词任务未完成时立即返回。
- 手机浏览器组件验证：5000 行虚拟列表仍只挂载可见行，播放、队列、详情返回保留滚动；歌词进度、暂停和重试按钮可触控。
- TypeScript 类型检查通过。构建签名 Android release APK，包名和签名延续 .18。
- 在开发环境请求 LRCLIB 的 `track_name=晴る&artist_name=ヨルシカ` 得到 HTTP 200 和多个带时间戳候选，接口允许跨来源访问。单元测试使用虚构歌词，不依赖在线目录稳定性。

## 边界

这里的“后台”是应用内异步处理，系统杀掉应用后下一次启动再续查。不会下载音频来做人声识别或强制对齐；MV 前奏、剪辑版与原曲的歌词时间仍可能有偏差。歌词库覆盖率和用户手机实际网络状况无法保证，标题不足、未收录或请求失败的条目会明确保留为未完成匹配。未接入用户的私人收藏夹或手机，不宣称全部歌曲均已匹配。
